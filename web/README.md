# Octopus Web

前端使用 React、TypeScript 和 Vite。

开发环境启动：

```bash
pnpm install
pnpm dev
```

Vite 默认监听 `http://localhost:5173`，并将 `/api` 请求代理到 `http://127.0.0.1:8080`。如需连接其他后端地址，可在启动时设置 `VITE_PROXY_TARGET`：

```bash
VITE_PROXY_TARGET="http://127.0.0.1:8080" pnpm dev
```

生产构建：

```bash
pnpm build
```

构建产物直接输出到 `static/out`，供 Go 二进制文件嵌入。

## 滚动与浮层布局

`src/globals.css` 在 `@layer base` 对 `*` 设置 `scrollbar-width: none`，原生滚动条默认全部隐藏；只有真实可滚动的容器显式加上 `.scrollbar`，作为由增强轨道接管的标记。`src/lib/overlay-scrollbars.ts` 与 `src/components/common/OverlayScrollbars.tsx` 在 `main.tsx` 的 Provider 下安装一次，识别所有带 `.scrollbar` 的原生滚动容器，用绝对定位的轨道覆盖原生滚动条位置，同时覆盖纵向、横向以及 `textarea`。`src/globals.css` 仍提供轨道的拇指色（由主题前景色经 `color-mix` 推导，亮/暗主题自动适配），增强本身为本地实现，未引入新依赖。

轨道不进入文档流、不占用布局尺寸，容器保持原有内容宽度与居中，也不需要靠预留滚动条槽位或补内边距维持对齐；容器原有的 `overflow`、`ref` / `scrollTop` / `scrollLeft` 用法不变，键盘滚动与原生 wheel、触摸滚动仍由原滚动容器处理，轨道支持真实滑块拖动与点击定位。

滚动条默认隐藏；原生滚动或操作轨道时显示，最后一次滚动或结束拖动约 1 秒后自动淡出。鼠标悬停整条轨道（不只滑块）或正在拖动时持续显示，透明轨道仍保留原有点击与拖动命中区。显示与隐藏使用 160ms 的透明度过渡，支持中途反向；触摸设备不启用悬停保持，系统开启减少动态效果时取消过渡。该行为对横向、纵向和 `textarea` 一致，不改变布局与祖先透明度。

新增滚动区域时：

- 只给真正会产生滚动的容器加 `.scrollbar`（`overflow-y-auto` / `overflow-x-auto` / 会溢出的 `overflow-auto`）。
- 不要给纯装饰性裁切容器加（`app-shell.tsx`、`channel/CardContent.tsx` 的卡片、`tabs.tsx` 的 `overflow: hidden`、`badge` / `progress` 等），它们没有真实滚动条可接管。
- 不要再为滚动条补 `px-2` / `pr-2` / `pb-2` 一类 gutter 补偿，保留容器原有业务内边距即可；轨道优先使用滚动容器自身已有的内边距，不足时再使用最近祖先既有的外侧留白，不跨越原有滚动或裁切边界。响应式标记（如 `max-md:scrollbar`）只在相应断点绘制轨道。
- 轨道 `aria-hidden`、不设置 `tabIndex`，不新增可聚焦控件，也不改变原有焦点与 Tab 顺序。轨道按下、抬起与点击取消默认行为以保留焦点，但继续传播到文档的外点监听；监听通过 `getOverlayScrollbarViewport(eventTarget)` 判断真实归属，只把自己内部的轨道当作内点，外部轨道仍关闭浮层。Popover、Select 与菜单的轨道留在对应内容树内，保留 Radix 原有内部捕获与点击关闭机制；Ctrl＋滚轮不接管，保留浏览器缩放。
- 轨道 host 作为父层首个绝对定位子节点，显式清零 margin，避免改变 `space-y-*` 的末子节点间距；host 恢复时保持相同插入位置。
- 热力图等横向滚动区域同时保留渐隐 mask 和底部滚动条。

MorphingDialog（`src/components/ui/morphing-dialog.tsx`）的视口容器用 `overflow-clip` 限制可见范围，避免焦点或 `scrollIntoView` 滚动容器本身。内容仍可能裁切溢出的子元素，因此浮层不要依赖绝对定位越出宿主卡片。设置中的密钥与账号表单通过 `MorphingDialogOverlayLayer` 挂到 `document.body`，由浮层自己承担视口高度约束、滚动和嵌套键盘处理；外点不丢弃草稿，提交期间禁用取消操作和 Escape 关闭。

移动端通过 `viewport-fit=cover` 让背景铺到边缘；`src/globals.css` 的四向 `--safe-area-*` token 统一约束内容。底部导航用动态 bottom inset 移位，滚动内容用 `pb-nav-clearance` / `h-nav-clearance` 留出导航净空；AppShell 本身不重复添加底部 inset。两类 MorphingDialog portal 使用 `--overlay-*` 四向边界，可用高度只由外层扣除一次，内部面板继续 `max-h-full` 并自行滚动。

Popover 与 Select 通过 `src/hooks/use-safe-area-insets.ts` 共享 resize / visualViewport.resize 的数值快照。碰撞边界累加调用者原有间距；Select 原有 4px 视觉间距通过 Radix sideOffset 参与碰撞计算，不使用计算后的位移越过安全边界。模型价格编辑复用居中的 MorphingDialog（受 `--overlay-*` 四向边界约束），正文在弹窗内独立滚动，取消与保存按钮固定在底部。

Toast 保留调用者显式 `offset` / `mobileOffset` 的优先级。Sonner 的移动端默认样式只按左侧 offset 计算卡片宽度，因此 `globals.css` 在其 600px 移动断点内将容器宽度改为分别扣除左右 mobile offset，卡片填满该容器；不对称 cutout、left/right/center 位置均使用同一可用宽度，桌面宽度与定位不变。

## 首页今日实时脉冲与网关驾驶舱

首页（`src/components/modules/home/`）聚焦今日实时态与网关巡检，和数据分析页共享可比较指标的统计来源：

- 顶栏右侧在首页视图下展示 SSE 实时连接状态胶囊（`connected` / `connecting` / `reconnecting` / `fallback`）和手动刷新按钮（同时刷新首页统计、配置查询并重置实时流）。
- 第一行四个今日核心指标卡片直接读取 `/api/v1/stats/today`、`/api/v1/stats/total`、`/api/v1/log/overview/stream` 与渠道/密钥/模型列表；实时并发卡片仅展示今日真实平均总耗时，不基于无 `ftut` 的概览流伪造首字延迟。
- 第二行展示今日 `00:00–23:00` 按小时实时流速曲线（`/api/v1/stats/hourly`），未来时段留空，支持切换成本/次数/Token 并提供进入“数据分析”页的快捷入口。上方汇总复用 `/stats/today` 的完整日聚合；小时分布只包含已采集请求明细的样本，覆盖不足时显示样本数与总请求数。
- 第三行左栏基于真实启用渠道、渠道 Key 最近状态码、测速延迟以及客户端 API Key 过期时间与 `max_cost` 预算进行健康巡检（高危异常与预警优先排序，支持跳转渠道/设置或直接按今日筛选切入指定渠道的分析页）；右栏由 `Home` 单点调用 `useLogOverview()` 订阅 `/api/v1/log/overview/stream`（不可用时降级每 10 秒轮询 `/log/active` 与第一页 `/log/list`），实时展示进行中请求耗时与近期请求状态（仅在真实 `upstream_status_code > 0` 时展示状态码，HTTP 200 失败仍标为失败）。
- 每次实时流连接成功后补拉完整活动请求及近期记录，避免最近 100 条概览快照漏掉较早开始的长请求；补拉期间收到的 SSE 更新优先合并，已完成请求不会被旧快照恢复为运行中。
- 渠道 Key 最近请求结果有效期为 30 分钟，按各 Key 的 `last_use_time_stamp` 判断；超时、从未请求或没有状态码的启用 Key 显示灰色“待验证”，不计入异常/告警。近期错误仍优先展示；没有近期错误但存在待验证 Key 时，渠道和顶部网关概览均不显示正常。卡片展示上次请求的相对时间，悬浮或键盘聚焦渠道行可查看各启用 Key 的最后结果与请求时间。原有每分钟时钟更新会使旧状态自动过期，无需产生模型探测请求。
- 渠道巡检按异常、告警、正常、待验证排序。巡检和实时动态卡片内的列表保留独立滚动，内容不足以滚动或滚到边界后允许继续滚动外层页面；可滚动的历史结果 Tooltip 仍独立限制滚动链。
- 渠道与密钥巡检等待渠道列表、客户端密钥列表及密钥统计全部就绪；顶部网关卡同时等待模型列表。任一必需查询失败时显示失败提示并可重试，停止输出健康或未启用结论。
- 第四行保留近 54 周全年活跃度热力图及渐隐/增强滚动条与键盘固定提示行为。

主页保留轻量接口与原有刷新节奏：`/stats/today`、`/stats/total`、`/stats/hourly` 每 10 秒刷新，全年热力图的 `/stats/daily` 每 1 小时刷新；分析页仍为 30 秒。接口名和缓存键虽然分别保留，今日/累计/日趋势在后端与分析页共用 `stats_usages` 历史和未落库增量的同一聚合函数；小时分布共用 `request_metadata` 的开始时间聚合，不运行整套性能分位数查询。

日期与小时统一采用请求开始时的服务器本地日历时间；例如昨天 23:59 开始、今天 00:01 完成的请求，完成后归入昨天及昨天 23 点时段。热力图也使用服务端返回的业务日作为日历锚点。历史数据范围以分析页现有聚合为准，不从旧总量/小时缓存推算缺失的多维或小时明细。实时并发、近期日志及配置巡检继续使用各自的实时流或配置查询。

## 数据分析与持久化元数据

分析页保留原有概览、日趋势与模型/API Key/渠道拆分，并增加用量与成本、性能、失败重试、小时流量及请求特征专题。趋势可选择输入/输出/缓存 Token、缓存读取占比、成功率、失败数和平均总耗时；各实体行可展开输入输出成本、缓存占比、单请求成本及费用占比。

筛选选项随所选日期范围更新：请求模型、实际上游模型、API Key 与渠道来自范围内的历史日聚合及未落库增量，响应方式、推理强度、任务类型、客户端协议与结果分类来自同一日期范围的请求元数据。选项接口 `api/v1/stats/analytics/dimensions` 使用与分析接口一致的 `period/start_date/end_date` 参数，仅按日期范围生成选项，不随其他筛选条件联动收窄；日期范围内不存在的已选项在选项成功加载后重置为“全部”。

渠道与 API Key 的历史统计按 ID 和名称快照共同区分；表格行标识、展开状态以及筛选选项值使用同一组合身份。改名或删除后复用 ID 时，不同名称的历史条目分别展示和筛选，删除实体不清除其历史用量。

`api/v1/stats/analytics` 的 `details` 返回精细采集覆盖、实际样本数、分位数、缓存写入/推理 Token、错误/最终上游状态分布、真实重试与恢复、小时流量、分钟峰值，以及流式/推理强度/客户端协议/任务类型拆分。缺失的上游用量明细和无样本指标返回 `null`，界面显示 `—`。P50/P95 以原始请求样本的 nearest-rank 计算，不对日分位数求平均。首字延迟仅使用成功且收到首字的流式请求；输出速度排除首字等待，用成功流式请求有效生成时长加权。

仅使用旧筛选时，原有汇总继续来自长期日聚合；启用响应方式、推理强度、任务类型、客户端协议或结果分类筛选后，所有汇总和趋势改用同一批已持久化请求元数据，`coverage.summary_source` 标记为 `request_metadata`，界面明确提示范围。旧请求缺少精细数据时仅参与原有日聚合，不能当作新指标为零。缓存读取量和占比使用独立的元数据采集覆盖：`observed_cached_token`、`cache_read_sample_count` 和可空的 `cache_read_ratio`。比例分子与分母仅包含缓存读取字段和标准化输入量同时已知的配对请求（`cache_read_input_token`），`cache_ratio_sample_count` 显示比例样本数；部分流式失败仅收到缓存量、尚无标准化输入时仍保存已知缓存量，但不参与比例计算；无上报时为 `null`，不使用旧聚合中的数值零推断未命中。汇总、趋势和各实体拆分均采用此口径，旧 `cached_token` 历史累计值继续保留。

跳过和熔断不计入真实转发/重试次数；重试恢复率为重试后成功请求 / 发生重试的请求。小时与分钟峰值按请求开始时刻、服务器时区归属；分钟 Token 峰值是请求用量的时间归属，不是实时生成吞吐。时段热力图按服务器小时合并所选日期。

元数据在调度后的请求结束时写入独立 `request_metadata` 表，长期保留并纳入 `include_stats` 备份；正文、图片、请求头、密钥值与自由格式错误内容不进入该表。实时日志窗口仍受内存和记录条数限制，清空实时日志不删除分析元数据。鉴权或请求解析阶段被拒绝、尚未进入转发调度的请求沿用原有统计范围，不纳入转发请求分析。

## 日志活动耗时

`src/api/endpoints/log.ts` 仅在解码 running / committed 网络快照时记录 `performance.now()` 观察锚点，并将服务端整体 duration 从纳秒转换为毫秒。同一请求的活动快照合并先投影到共同观察时刻，避免旧分页或 SSE 导致倒退；终态直接采用服务端值，不把 UI 推算值写回。

日志卡片与活动详情共用 `src/components/modules/log/use-live-duration.ts` 的单个 1 秒时钟。仅有锚点的可见活动指标订阅；页面隐藏时暂停，恢复后按单调时间差补齐，最后一个订阅卸载后清理时钟和监听。开始时刻仅用于时间展示，不参与客户端耗时计算；重试和虚拟列表重挂载不重置总耗时。

日志概览与详情快照还包含可选的 `upstream_model_name` / `response_model_name`。前者取参数覆盖、追加和协议修补之后的真实出站请求，后者只取原始上游响应声明（包括各协议原始流帧），不从转换器结果或候选名补造。字段属于当前尝试，新尝试开始清空，终态以最后尝试结果接管；空值表示未知。实时日志模型中的两字段仍为 `gorm:"-"`，不向旧日志表新增列；新请求另以轻量分析元数据保存这些模型快照，历史内存日志不会补录。

只有真实出站模型与原始返回模型均已知且逐字不同时，卡片和详情才显示文字徽标「模型不一致」；徽标使用与请求状态一致的 10px 字号，返回模型名不重复列出。悬浮时通过与渠道重试提示相同的圆角卡片 Tooltip 分行展示完整的上游请求模型与响应返回模型，长名称换行、超高内容可独立滚动；aria-label 保留完整 pair。候选模型仍用于尝试历史与计价，不将模型差异当作请求失败。短视口详情标题最多占面板内容高度的 40%，可独立滚动查看完整名称，避免挤掉总耗时与其他指标。

## 模型按时段价格

模型创建和编辑支持可选的 `price_schedule`。基础价和各时段均包含输入、输出、缓存读取、缓存写入四项美元 / 百万 Token 单价；未命中时段或命中排除日期时使用基础价。卡片展示基础价和价格时段数量，编辑时查看完整规则。

规则指定 IANA 时区（默认 `Asia/Shanghai`），时间使用 `HH:MM`，结束允许 `24:00`。区间包含开始、不包含结束，支持跨午夜；跨午夜规则按开始日匹配星期。`weekdays` 为 0（周日）至 6（周六），省略或空数组表示每天；规则在一周内不能重叠。`excluded_dates` 使用该时区的 `YYYY-MM-DD` 日历日期，排除当天全部时段，法定节假日需手动维护。

整个请求按其开始时间选价，流式输出跨时段仍使用同一组单价。规则保存在模型价格的可空 JSON 列中，随模型列表、缓存和备份导入导出保留；旧记录无规则时沿用原计价。重建价格保留手工时段配置，清理无价格模型也会保留带时段规则的模型。价格同步源仍为 models.dev，当前同步只更新预置基础价，时段规则在本地配置。

供应商还存在长上下文阶梯、Batch/Flex/加速服务档位、缓存有效期及多模态/工具用量等计价维度；这些条件需要对应的请求或用量信息，当前四项 Token 单价与时段规则不自动处理这些维度。

## 分组成员首尾移动

分组创建和编辑的已选模型列表提供“移到顶部 / 移到底部”。按钮只修改当前草稿，保存或创建时沿用列表顺序生成 priority；取消不会写入。首项、末项、单成员及正在删除或拖拽的行禁用对应操作。列表卡片不提供这两个按钮，继续使用原有拖拽落点持久化排序。

## 日志渠道密钥标识

每次真实渠道尝试记录 `channel_key_id` 和可选的 `channel_key_remark`。备注取该次使用的 Key 的 `Remark`，在开始尝试时去除首尾空白并保存快照；不记录密钥正文，不拼入渠道名称或改变统计维度。

主卡片取最后一次非 skipped / circuit_break 的真实尝试，仅在其 Key 有备注时显示备注名，没有备注则不显示（不再单独列出 ID）；重试提示、尝试历史和选中尝试详情保持原行为，分别显示各自的 ID 与备注。没有正 ID 时不显示标识；跳过项不会补查备注。长备注换行，重试提示中的尝试列表限制高度并可独立滚动。

重试提示的 `data-scrollable-tooltip` 标记仅用于保留该内容的悬停与内部滚动；离开内容、页面外部滚动或 Escape 仍关闭。未标记的提示保持原有行为。

实时日志当前保存在服务进程的内存 store。修改备注后，已有记录仍显示旧快照，新请求捕获新备注；实时日志窗口不跨重启恢复。请求结束时，渠道 Key ID 与备注快照另存入轻量分析元数据的尝试记录，随统计备份长期保留；不保存密钥值。

## 日志列表内存窗口

前端概览与旧日志流的实时缓存最多保留最近 100 条已完成记录（成功、失败或取消），运行中与已提交响应但尚未结束的请求独立保留。实时更新会同时裁剪概览状态与旧流写入的查询缓存；虚拟滚动只减少 DOM 数量，不能替代数据淘汰。虚拟列表移除行时会清理旧行键的尺寸缓存，并重新测量可见行，避免测量缓存随长期推送累积。

概览流可用时停止旧日志流及其活动请求轮询，避免重复接收和缓存包含请求/响应正文的旧流记录。概览断开时恢复旧流与最新一页补拉，重新连上概览后再次停止旧流。正文与图片继续通过详情的按需接口读取。概览订阅的服务端缓冲区满时关闭该订阅，客户端重连后重新获取快照，避免静默丢失终态而长期保留已结束的活动请求。

## 日志上游响应码与失败正文

日志请求与各次尝试的可选 `upstream_status_code` 只记录真实上游 HTTP 响应码：请求级取最终实际转发尝试，各次尝试独立保存。未收到 HTTP 响应、跳过/熔断或旧记录未采集时为未知，缺失值与 0 都不显示；不从错误 `code`、客户端状态码或渠道 Key 最近状态推断。失败/取消请求及失败/取消尝试显示「上游 HTTP {code}」，HTTP 200 中的业务或流式错误仍是失败，不显示为成功。

详情仅在选中最后一次非 skipped / circuit_break 的实际尝试且请求已失败/取消时，额外加载请求的最终错误正文；早期失败尝试只显示自己的诊断，不回退到另一尝试的最终错误，也不展示后一次尝试的响应正文。正文继续通过鉴权正文 API 按需读取，打开中的详情在进入终态时重新获取。非流式失败正文为实际下发给客户端的协议转换后内容；流式失败正文为客户端最后失败事件的 payload，不是完整 SSE transcript。正文沿用现有日志上限与截断标记，概要不包含正文。

## 日志正文预览与已保存内容

请求正文与响应正文都通过鉴权正文 API 按需读取，概览只携带响应正文的保存元数据（`response_content_preview`）。请求侧不生成保存元数据，也不提供大小信息；旧记录没有该字段时不补造原始大小，继续沿用正文面板原有的「内容已截断」徽标。

响应的保存元数据由后端给出 `original_bytes` / `stored_bytes` / `format`（`json` 或 `text`）以及可选的 `reason` 与 `omissions`：`reason` 为 `size_limit`（超出保存上限）或 `invalid_utf8`（内容不是有效 UTF-8）；`omissions` 逐项给出被改写字段的 JSON Pointer 路径（根为 `""`）、种类（`string` / `array` / `object` / `binary`）与原始/保存的字节数或元素数量；超过收录上限的其余省略数量汇总在 `omitted_details`。

响应保存上限仍为 256 KiB，小响应按原字节保存；超限 JSON 优先保留 `id` / `model` / `status` / `object` / `usage` / `finish_reason`，普通字符串最多保留 16 KiB 解码后的 UTF-8 内容，对象/数组最多尝试保留 256 项，数组只保留前缀以维持索引。明确的 base64 大字段保存为空字符串并在独立元数据中标记，不占用普通文本的预算。省略详情最多 32 条、每条路径最多 512 字节；字段字节数按解码值统计，正文大小按实际序列化字节统计。非 JSON 或无效 UTF-8 保留有效前缀，请求正文无固定大小上限，均未改变实际客户端响应。

结构化预览直接扫描原始 JSON 并在预算内写出，不构建完整解码树；未保留的元素只扫描、计数，超长字符串也不整体解码复制。预览最多下钻 64 层嵌套容器，超过深度的子容器被省略并记录损失；此限制只作用于超限响应的日志预览，不改变客户端响应或小响应原字节保存。

有损时的正文面板默认提示「仅显示部分响应」，说明完整内容未保留，复制和下载也仅包含当前内容；原始与保存大小、原因、被省略字段路径与数量收在默认折叠的「查看详情」中，支持点击或键盘展开。结构化预览是超限 JSON 的改写结果，不是原始 JSON，也不补伪造的占位字段或省略号；`format` 未知或正文不是对象/数组时退回文本视图。树视图默认展开浅层、更深节点逐个展开（库的 `shortenTextAfterLength` 折叠长字符串），被改写的字段键旁只标注「已省略」，不把省略内容当作完整展示。

窄屏有损响应面板的滚动高度上限为 50dvh，给损失说明、换行工具栏和正文留出空间；普通/旧响应继续使用原来的 30dvh，桌面布局不变。

面板可切换「结构化预览」与「文本视图」（后者不额外格式化，直接显示实际保存的正文，可能已是裁剪后的 JSON 或截断后的前缀）。「复制」与「下载」都作用于同一份已保存内容，不是原始完整响应：下载按正文是否为有效 JSON 使用 `application/json` 加 `.json`，否则使用 `text/plain;charset=utf-8` 加 `.txt`；尚未加载或仍在流式输出时不提供这两个操作。正文复制等待原生剪贴板写入完成；接口不可用或写入被拒绝时沿用旧式复制命令，只有命令明确成功才提示成功，两种方式均失败则提示失败并清除上次成功状态。临时复制节点无论成功或失败都会移除，并恢复复制按钮焦点。错误块及其复制行为不变，也未新增错误相关逻辑。

## 日志生成图片预览

响应正文的鉴权按需接口 `/api/v1/log/:request_id/response-body` 额外返回 `images: [{ "src": "..." }]`，无图时为 `[]`；请求正文、日志列表及概览/详情 SSE 不包含该图片数组。新旧详情布局都从该接口读取图片，图片块独立收起/展开且默认展开；切换结构化预览与文本视图不重置折叠选择，关闭详情后重新打开恢复默认展开。后端本地缓存的图片 src 为应用目录下的鉴权路由 `/api/v1/log/:request_id/images/:image_index`（索引从 0 起），与正文接口同处 Cookie 鉴权分组，前端按部署目录解析，根目录与子目录部署均正确；远程 http(s) 地址保持原样。

点击生成图片可打开独立的放大查看层，图片按可用视口完整显示；查看卡片沿用项目的圆角、边框与 `bg-card`，关闭位于右上角，底部使用主色「保存图片」与柔和底色「打开原图」按钮。缩略图与查看卡片、图片采用稳定共享布局身份和 `stiffness: 400` / `damping: 30` 弹簧往返，图片保持自然宽高比；独立遮罩采用项目现有的浅/深色与模糊样式，默认 0.2 秒淡入淡出。键盘打开和 Escape 即时切换；系统减少动画偏好通过原生媒体查询实时订阅，关闭共享形变，仅保留 0.15 秒遮罩淡入淡出。图片私有动效显式使用该实时偏好控制，应用全局 `MotionConfig reducedMotion="user"` 不变。关闭按钮、Escape 或点击图片外的空白区域仅关闭图片，不关闭日志详情，焦点返回原缩略图；查看层沿用日志的嵌套浮层登记与 Tab 焦点循环，窄屏操作按钮至少 44px 高。

缩略图下与放大层均提供「保存图片」和「打开原图」。保存直接读取图片源的完整二进制，按图片 MIME 选择文件后缀，不重新编码，也不依赖可能被裁剪的响应正文；同源源地址携带 Cookie，远程读取不携带应用凭据、不发送 Referer。远程服务器未允许 CORS、链接失效或读取失败时显示保存失败，可通过「打开原图」由浏览器保存；不增加服务端远程图片代理。加载失败的图片保留原图链接并禁用保存，不影响其他图片。

图片在正文裁剪前从最终客户端生成响应中提取：Images 的 `data[]`，以及 Responses 中已完成 `image_generation_call` 的 `result`。Responses 图片资格以最终输出为准，不要求客户端请求声明工具，因此渠道通过 `param_append` 或 `param_override` 注入的生图工具同样可以预览。不扫描 Markdown、输入图或普通文本；每项优先使用可识别的 Base64，再使用同项合法 URL，保持顺序，不去重。内联图片仅嗅探至多 512 字节前缀，支持 PNG/JPEG/WebP；远程地址仅接受带 host 的 HTTP/HTTPS，由浏览器直接加载且不发送 Referer，服务端不下载、代理或归档图片。

完整内联图片流式解码后写入配置文件旁的 `log-images` 目录（默认 `data/log-images`，显式 `--config` 时随配置目录隔离），日志记录只保留文件引用、类型与大小，不再长期保存完整 Base64。图片文件保留完整二进制，支持超过正文 256 KiB 保存上限的图片，但不会扩大正文上限或改变有损字段提示；正文工具栏的复制、下载仍精确作用于已保存正文，不包含独立图片，图片通过自己的「保存图片」操作导出。图片二进制不入 SSE、列表、数据库或备份归档，进程启动时只清理该目录自身的 `image-*` 普通文件。全部本地预览共用一个 512 MiB 总预算（包括正在写入、读取结束前保留及删除失败的文件）：预算不足或写文件失败时跳过该图片预览并告警，不淘汰既有日志、也不改变客户端响应；缓存目录初始化失败时告警并禁用本地预览，服务与远程图片仍可用。清空、淘汰与过期清理释放对应文件（已开始的读取句柄在关闭后删除），远程 URL 由浏览器直接加载、过期或损坏时原位显示加载失败，其他图片仍可查看。512 MiB 是图片二进制总预算；完成记录另受最多 100 条与动态正文预算两个上限约束：容量按有效总内存的 1/16（最多 512 MiB）计算，再随可用内存及安全余量收紧；每次完成及每 5 秒重评，Linux 同时尊重容器及父组内存限额。最新完成的一条和进行中请求始终保留，淘汰其他记录时一并释放其图片。探测不可用时回退 64 MiB，具体公式与平台行为见仓库 README 的存储说明。

## 反向代理子目录与 PWA

生产页面可以部署在 `/`、`/octopus/` 或其他应用目录。`src/lib/base-url.ts` 基于 `document.baseURI` 统一解析 API、导入导出、三条日志 SSE 和 Service Worker URL；构建资源继续使用 Vite 的相对 base。

反向代理必须同时满足：

- 将无末尾斜杠的入口（如 `/octopus`）308 重定向至 `/octopus/`，保留查询参数。
- 将 `/octopus/*` 剥离目录前缀后转发为后端的 `/*`，保留 method、body、query、cookie 和 Authorization。后端仍在根路径挂载路由和嵌入资源。
- SSE 响应不得缓冲；API 不得缓存。导出保留 Content-Disposition，认证保留 Set-Cookie。

Service Worker 注册 scope 为当前应用目录。shell / static 缓存名为 `octopus-${encodeURIComponent(basePath)}-shell-v4` / `static-v4`，各目录独立；`octopus-font` 跨目录共享并保留。仅根目录的 worker 额外清理旧 `octopus-shell-v数字` / `octopus-static-v数字` 缓存，子目录不认领这些旧根缓存。

“强制刷新”由主线程删除当前目录的非字体缓存，并只注销 scope 精确匹配当前目录的注册后刷新；不向可能仍控制页面的旧根 worker 发送清理消息，不删除其他目录或无关产品缓存。离线时只提供已经缓存的页面壳、静态资源和字体，未缓存的 API 仍不可用，既有认证行为不变。

同 origin 下的多目录部署不隔离认证：HttpOnly cookie 仍为 Path=/，登录偏好与 localStorage 仍共享。目录缓存隔离不代表多账户或多后端实例的认证隔离。
